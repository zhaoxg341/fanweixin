## 0. 先记住一句话

Android 项目再大，代码永远只有三种角色：

| 角色 | 干什么 | 本项目里的例子 |
|---|---|---|
| **界面** | 把数据显示出来、接收点击 | `MainActivity`、`ChatsFragment`、`ChatAdapter` |
| **数据** | 存数据、算数据、提供数据 | `ChatManager`、`ChatBean`、`MessageDao` |
| **通道** | 跟外界（网络/文件/数据库）打交道 | `ChatClient`、`ChatServer`、`WeixinDbHelper` |

读任何一份代码，先问自己：**这个文件属于哪一类？** 想清楚这一点，你就不会迷路。

## 1. 工程目录地图（先看这里，别急着看代码）

打开 `WeiXinDemo/app/src/main/`，你会看到：

```
main/
├── java/cn/itcast/weixin/        ← 所有 Java 代码，按"职责"分文件夹
│   ├── activity/     Activity：一整屏界面（有标题栏、能跳转）
│   ├── fragment/     Fragment：屏幕里的一块区域（配合 Tab 切换）
│   ├── adapter/      Adapter：列表"每一行长什么样"的翻译官
│   ├── bean/         数据模型：只有字段 + getter/setter 的"纯数据类"
│   ├── db/           数据库：建表 + 增删改查（DAO）
│   ├── utils/        工具类：数据管理、网络、偏好设置
│   ├── view/         自定义控件：自己画的控件
│   └── WeixinApp.java 全局入口（App 一启动就跑）
│
├── res/                          ← 所有资源，注意：资源名不能带点号！
│   ├── layout/       XML 布局：界面"长什么样"
│   ├── drawable/     图标（矢量图）
│   ├── drawable-nodpi/ 照片（jpg，放这个目录不会自动缩放）
│   ├── values/       颜色、字符串、主题（colors.xml / strings.xml）
│   ├── menu/         菜单
│   └── mipmap/       应用图标
│
├── assets/           ← 原始数据文件（不会被打包成资源 id）
│   └── weixin.json   离线演示用的假数据
│
└── AndroidManifest.xml  ← 应用"户口本"：有哪些页面、谁先启动、要什么权限
```

**关键理解**：`java/` 里放**逻辑**，`res/layout` 里放**样子**，两者通过 **`R.id.xxx`** 这个"名字"连接起来。

> 记忆技巧：`R` 就是 resources（资源）的缩写。你在 XML 里写 `android:id="@+id/tv_name"`，
> 编译后系统就生成一个 `R.id.tv_name` 整数常量，Java 里 `findViewById(R.id.tv_name)` 就能拿到那个控件。

## 2. Java 知识在本项目的落点（对照着学，最有效）

| Java 知识点 | 在本项目哪里能看到 | 怎么理解 |
|---|---|---|
| **类与对象** | `ChatBean.java` | 一个"会话"就是一个对象，有 id/name/avatar 等属性 |
| **封装** | 所有 Bean 的 `private` 字段 + `get/set` | 字段不让人直接改，必须走方法，方便加校验 |
| **继承 `extends`** | `MainActivity extends AppCompatActivity` | 白拿父类的全部能力（生命周期、`setContentView`），只需重写你要改的方法 |
| **接口 `implements`** | `ChatAdapter extends BaseAdapter`、`OnClickListener` | 接口=一份"必须实现的方法清单"，系统按清单回调你 |
| **抽象方法 / 重写 `@Override`** | `getView()`、`onCreate()` | 父类说"这一步你自己实现"，你重写它 |
| **匿名内部类** | `new View.OnClickListener(){ onClick(){...} }` | "临时造一个只实现一次的对象"，用来接点击事件 |
| **静态 `static`** | `ChatManager.getChats()` | 静态方法不需要 new 对象，全项目共用一个数据源 |
| **单例模式** | `ChatClient.get()`、`WeixinDbHelper.get()` | 全局只允许一个实例，避免重复连接 / 重复打开数据库 |
| **集合 `List` / `Map`** | `List<ChatBean> CHATS`、`Map<Integer,List<MsgBean>>` | List=有序列表，Map=键值对（用 chatId 找消息） |
| **泛型 `<T>`** | `List<ChatBean>`、`Map<String,String>` | 尖括号里写类型，取出时不用强转 |
| **异常 `try/catch`** | `ChatClient.handleLine()` | 网络/解析随时可能出错，捕获后不影响程序继续跑 |
| **线程 `Thread`** | `ChatsFragment.loadData()`、`ChatClient.loop()` | 耗时操作（读文件/连网络）必须放后台，否则界面卡死 |
| **内部类 + 回调** | `ChatManager.OnChatChangedListener` | "我变了就通知你"，是实现界面自动刷新的关键 |
| **字符串 `String`** | `content.trim()`、`replace("\n"," ")` | 判空、去空格、替换，是防御性编程的基本功 |

**给你的建议**：Java 不用先学完再学 Android。**遇到看不懂的语法就查，带着问题学，记得最牢。**

## 3. Android 核心概念在本项目的落点

### 3.1 四大组件（本项目用了两个）

| 组件 | 作用 | 本项目 |
|---|---|---|
| **Activity** | 一个"屏幕" | `LoginActivity`（登录页）、`MainActivity`（主界面）、`ChatActivity`（聊天页）、`UserInfoActivity`（个人资料）、`MomentsActivity`（朋友圈） |
| **Fragment** | 屏幕里的一块区域 | 微信/通讯录/发现/我 四个 Tab 各是一个 Fragment |
| Service | 后台长期运行 | 本项目未用（在线聊天用线程实现） |
| BroadcastReceiver | 接收系统广播 | 本项目未用 |

### 3.2 Activity 生命周期（这是理解 Android 的第一道坎）

```
onCreate()   → 页面第一次被创建，在这里 setContentView + findViewById（只跑一次）
    ↓
onStart()    → 即将可见
    ↓
onResume()   → 可见且能交互（从别的页面返回时也会回到这里）
    ↓
── 用户点了别的页面 ──→ onPause() → onStop()
    ↓
onDestroy()  → 页面销毁，在这里反注册监听器，防止内存泄漏
```

**本项目的实际应用**（很典型的三个用法）：

- `onCreate()`：`MainActivity` 里遍历四个 Tab 设置点击事件，然后 `selectTab(0)` 显示第一个。
- `onResume()`：`ChatsFragment` 每次回到前台都 `refresh()`，所以从聊天页返回时列表能显示最新消息。
- `onDestroy()`：`MainActivity` 里 `ChatClient.get().removeListener(...)`，**用完的反注册掉**，否则 Activity 销毁了还被监听器引用着，就会内存泄漏。

### 3.3 Activity 之间怎么传数据

看一眼 `ChatsFragment.onItemClick()`：

```java
Intent intent = new Intent(getActivity(), ChatActivity.class);
intent.putExtra("chatId", chat.getId());     // 存数据
startActivity(intent);                        // 跳过去
```

ChatActivity 里取出来：

```java
int chatId = getIntent().getIntExtra("chatId", -1);  // 后面那个是"取不到时的默认值"
```

> 记住这个模式：**Intent = 一张"车票"**，票上写着"去哪个页面" + "带什么行李"。

### 3.4 列表显示三件套（ListView + Adapter + item 布局）

这是 Android 最常考、也最能体现"分工会"的知识点，本项目 `ChatsFragment` 就是标准示范：

1. **数据**：`List<ChatBean>`，放在 `ChatManager` 里
2. **item 布局**：`item_chat.xml`，定义"一行"长什么样
3. **Adapter**：`ChatAdapter`，回答三个问题——共几行（`getCount`）、第 n 行是什么（`getItem`）、第 n 行怎么画（`getView`）

**`getView()` 里的 ViewHolder 模式（重点，面试也爱问）**：

```java
if (convertView == null) {                    // 这一行的"壳"是空的 → 第一次，需要新建
    convertView = inflate(...);               // 把 XML 变成 View
    holder = new ViewHolder();                // 把 5 个控件的引用装进一个小盒子
    holder.tvName = convertView.findViewById(R.id.tv_name);
    ...
    convertView.setTag(holder);               // 盒子贴在这行上
} else {
    holder = (ViewHolder) convertView.getTag(); // 壳是旧的 → 直接取下盒子用
}
holder.tvName.setText(...);                   // 只更新内容，不重建控件
```

**为什么这么做**：ListView 只创建屏幕内可见的那十几行，滑出去的行会被回收再用。如果不复用、每次 `findViewById`，滑动就会卡。所以——**复用壳（convertView）+ 缓存控件引用（ViewHolder）**。

### 3.5 资源与 AndroidManifest

`AndroidManifest.xml` 里每个 Activity 都要登记：

```xml
<activity android:name=".activity.LoginActivity" android:exported="true">
    <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent-filter>
</activity>
```

- 带 `MAIN` + `LAUNCHER` 的那个，就是**点图标后第一个打开的页面**（本项目是 `LoginActivity`）。
- 其它 Activity 默认 `exported="false"`，只允许应用内部跳转，更安全。

## 4. 三条必须打通的"调用链"（读代码的核心方法）

> **读代码不要一行一行地读，要顺着"一条链"读。** 下面三条链打通了，这个项目你就真正看懂了。

### 链路 A：点一下底部 Tab，屏幕怎么变的？

```
手指点"通讯录"
   → MainActivity 里注册的 OnClickListener.onClick()
   → selectTab(index)
   → FragmentTransaction.add() / show() / hide()
   → ContactsFragment.onCreateView()  → 加载 fragment_contacts.xml
                                     → onViewCreated() → 找到 ListView、设置 Adapter
```

关键代码在 `MainActivity.selectTab()`（第 125 行起）。注意它用 **add + show/hide** 而不是 `replace`：

- `replace`：每次切换都销毁重建页面 → 列表滚动位置丢失
- `add` 一次 + `show/hide`：页面留着，切回来还是原样

**看懂这一条链，你就懂了 Fragment 管理和事务提交（commit）。**

### 链路 B：列表里的字是怎么显示出来的？

```
ChatManager.getChats()  ← 数据源（List<ChatBean>）
   → ChatAdapter.setData(list) → notifyDataSetChanged()   ← 告诉列表"数据变了，重画"
   → ListView 回调 ChatAdapter.getView(position, ...)
   → inflate(item_chat.xml) + ViewHolder 绑定
   → holder.tvName.setText(RemarkDao.displayName(chat.getName()))  ← 真正的"赋值"
```

**注意最后一行**：为什么不是直接 `chat.getName()`？因为要**备注优先**。所有显示名字的地方都统一调 `RemarkDao.displayName()`，所以改完备注，会话列表 / 通讯录 / 聊天标题会一起变。这是**"单一出口"**思想，很值得学。

### 链路 C：发一条消息，对方怎么收到的？（本项目最有价值的一条链）

```
【我的手机】
ChatActivity 点"发送"
  → ChatManager.send(chatId, text)
      ├─ 存进内存 List<MsgBean>
      ├─ MessageDao.insert()        → 写进 SQLite（下次打开还在）
      └─ ChatClient.get().send(对方昵称, text)
            → sendLine(JSON) → Socket 输出流写出，结尾加 "\n"

                    ↓  一行 JSON 通过网络传出去

【电脑上的 ChatServer】
  reader.readLine() 读到这一行
  → 解析出 type=msg, to=对方昵称
  → 从转发表 Map<昵称, 连接> 里找到对方的连接
  → 原样转发过去（对方不在线就回一句 notice）

                    ↓

【对方手机】
ChatClient 后台线程 reader.readLine() 读到
  → handleLine() 解析 JSON
  → mainHandler.post(...)     ← 关键：从后台线程切回主线程！
  → ChatManager.receiveRemote(发送人, 内容)
      ├─ findOrCreateChat()：会话不存在就自动新建一个
      ├─ 存内存 + 写数据库
      ├─ 未读数 +1
      └─ notifyChanged() → 广播给所有监听器
            → ChatsFragment.refresh()   ← 会话列表自动刷新
            → ChatActivity 刷新         ← 聊天页自动刷新
            → MainActivity 更新红点
```

**这条链里藏着 4 个 Android 核心考点**，务必吃透：

1. **耗时操作必须在子线程**：网络读写放在 `loop()` 后台线程里，绝不放在主线程，否则 → ANR（应用无响应）。
2. **子线程不能碰界面**：所以读到的消息用 `mainHandler.post()` 扔回主线程再处理。**"网络在后台，界面在主线程"是铁律。**
3. **回调 / 观察者模式**：`ChatManager.OnChatChangedListener`。数据一变就通知所有关心它的人，界面自己刷新 —— 不用在各个页面写"手动刷新"代码。
4. **协议要能"分帧"**：为什么每条消息结尾写 `\n`，读的时候用 `readLine()`？因为 TCP 是**字节流**，没有边界，两条消息可能粘在一起。**用换行当分隔符，是最简单可靠的解决办法。** 这就是"粘包/拆包"问题的入门答案。

## 5. 数据存在哪？两种持久化方式

### 5.1 SharedPreferences —— 存"几个小设置"

`AppPrefs.java` 就是它的封装，存昵称、服务器地址、端口、是否在线模式：

```java
SharedPreferences sp = context.getSharedPreferences("weixin", Context.MODE_PRIVATE);
sp.edit().putString("my_nick", "赵学刚").apply();   // 写
String nick = sp.getString("my_nick", "默认昵称");   // 读（第二个参数是默认值）
```

适合：开关、账号、上次填过的地址。**不适合存大量数据。**

### 5.2 SQLite —— 存"很多条记录"

`WeixinDbHelper.java` 建了三张表：

| 表 | 存什么 | 关键字段 |
|---|---|---|
| `t_message` | 聊天记录 | chat_id（属于哪个会话）、content、from_me、time、ts |
| `t_remark` | 联系人备注 | contact_name、remark |
| `t_chat` | 在线新建的会话 | chat_id、name、avatar、last_msg |

DAO（Data Access Object）的写法看 `RemarkDao`，标准套路是：

- **写入**：`ContentValues` 装值 → `insert()` / `update()` / `delete()`
- **读取**：`query()` 得到 `Cursor` → `while(cursor.moveToNext())` 逐行取 → **`cursor.close()`**（一定要关，否则泄漏）
- 用 `?` 占位符传参：`delete(TABLE, "contact_name = ?", new String[]{name})`，**不要拼字符串**（防 SQL 注入）

> **性能小技巧**：`RemarkDao` 在 SQLite 之上又加了一层 `HashMap` 内存缓存。因为 `getView()` 滑动时每行都会调一次，每次都查库会卡。**读走缓存，写同时更新缓存 + 落库** —— 这叫"缓存穿透优化"，是前端/移动开发的通用思路。

## 6. 通用方法：拿到任何一个陌生项目，按这五步读

1. **看 `AndroidManifest.xml`** —— 找出启动页是谁，一共有哪几个页面，有没有权限申请。
2. **看 `res/layout` 的文件名** —— 快速知道这个 App 有哪些界面、每个界面大概长什么样。
3. **从启动 Activity 的 `onCreate()` 入手** —— 顺着"谁跳转到谁"画出页面流程图。
4. **找"数据从哪来"** —— 是读网络？读数据库？还是读 assets 里的 JSON？找到那个类。
5. **挑一个最典型的交互（比如"发送"），顺着调用链从头跟到尾** —— 跟完这一条，整个项目的套路你就懂了。

## 8. 调试技巧与常见坑

### 调试三板斧

1. **Logcat**：`Log.d("TAG", "值 = " + value)`，在 Android Studio 底部 Logcat 面板按 TAG 过滤。**"打日志"是最有效的排查手段**，比盯着代码想快十倍。
2. **断点调试**：在行号左边点一下打断点 → 用"小虫子"图标（Debug）启动 → 程序停在那里，可以看每个变量的值、一步步走。
3. **Toast 兜底**：不确定某段代码到底有没有执行，先 `Toast.makeText(...).show()` 弹一下。

### 本项目踩过的坑（你以后一定会遇到）

| 坑 | 现象 | 原因 & 解法 |
|---|---|---|
| **资源名不能带点** | 头像不显示 | JSON 里写 `avatar1.jpg`，但资源名是 `avatar1`。解法：`getIdentifier()` 前先去掉扩展名 |
| **主线程做网络** | 界面卡死 / 崩溃 | 网络必须放子线程，结果用 `Handler.post()` 回主线程 |
| **反注册监听器** | 内存泄漏、诡异崩溃 | `onDestroy` 里把 `addListener` 的监听器 `removeListener` 掉 |
| **ListView 嵌在 ScrollView 里只显示一条** | 列表高度不对 | 需要自定义 ListView 重写 `onMeasure()` |
| **改完数据界面不刷新** | 值变了但界面没变 | 忘了 `notifyDataSetChanged()` |
| **重连竞态** | 改服务器地址后出现两条连接 | 用"代次 generation"标记，旧线程发现自己过期就退出 |
